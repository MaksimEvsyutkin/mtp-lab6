## Описание проекта

В рамках лабораторной работы №6 «Веб-программирование на Python» разработано асинхронное веб-приложение на базе современного веб-фреймворка **FastAPI**. Приложение включает в себя серверную генерацию HTML-страниц с использованием шаблонизатора **Jinja2**, RESTful JSON API с валидацией через **Pydantic**, постоянное хранилище данных на базе **SQLite**, а также систему обмена сообщениями в реальном времени на основе протокола **WebSockets**.

## Выполненные задания (Вариант 2)

Согласно методическим указаниям для **варианта 2**, в полном объеме реализованы 3 задания средней сложности и 2 задания повышенной сложности:

### Задания средней сложности

1. **Задание №2: Страница с формой (имя &rarr; приветствие)**
   - Реализованы маршруты:
     - `GET /greet`: отображение HTML-страницы с формой ввода имени.
     - `POST /greet`: обработка отправленной формы с извлечением поля `username` через `fastapi.Form`, валидация и генерация персонализированного ответа вида `Привет, <Имя>!`. При пустом вводе выводится дружелюбный fallback `Привет, незнакомец!`.
   - Шаблон: [`templates/greet.html`](templates/greet.html).

2. **Задание №4: Страница с таблицей данных**
   - Реализован маршрут `GET /table`.
   - Сервер запрашивает актуальный список записей пользователей из базы данных SQLite и динамически рендерит стилизованную HTML-таблицу со столбцами: ID, логин (username), ФИО, роль и дата регистрации.
   - Шаблон: [`templates/table.html`](templates/table.html).

3. **Задание №7: FastAPI endpoint возвращает JSON**
   - Реализован REST endpoint `GET /api/info`, возвращающий метаданные лабораторной работы, информацию о студенте, группе, номере варианта и перечень выполненных задач в формате JSON.
   - Реализован REST endpoint `GET /api/users`, сериализующий список пользователей из базы данных в строгом соответствии со схемой Pydantic `UserResponse`.
   - Интерактивная OpenAPI/Swagger документация доступна по адресу `/docs`.

### Задания повышенной сложности

4. **Задание №2: FastAPI с базой данных (SQLite)**
   - В модуле [`app/database.py`](app/database.py) реализован менеджер базы данных `Database` на базе `sqlite3`.
   - Автоматически создаются таблицы `users` (уникальный `username`, `full_name`, `role`, `created_at`) и `messages` (`author`, `content`, `created_at`).
   - При первом запуске выполняется автоматическое наполнение начальными тестовыми данными (seed data).
   - Предусмотрен endpoint `POST /api/users` с кодом ответа `201 Created` и валидацией входных данных через Pydantic-модель `UserCreate`.

5. **Задание №6: Приложение чат (WebSocket FastAPI)**
   - Реализован маршрут `GET /chat` для отображения клиентского интерфейса группового чата ([`templates/chat.html`](templates/chat.html)).
   - Реализован WebSocket endpoint `/ws/chat` в [`app/main.py`](app/main.py).
   - В модуле [`app/websocket.py`](app/websocket.py) реализован менеджер соединений `ConnectionManager`, отслеживающий активные клиентские сокеты и выполняющий широковещательную рассылку (broadcast) сообщений всем подключенным пользователям.
   - Все отправленные в чат сообщения асинхронно сохраняются в таблицу `messages` базы данных SQLite и сопровождаются временными метками.

## Инструкция по локальному запуску

### 1. Клонирование репозитория
```bash
git clone https://github.com/MaksimEvsyutkin/mtp-lab6.git
cd mtp-lab6
```

### 2. Создание и активация виртуального окружения
```bash
python3 -m venv .venv
source .venv/bin/activate   # macOS / Linux
# или .venv\Scripts\activate на Windows
```

### 3. Установка зависимостей
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Запуск сервера разработки
```bash
python3 main.py
# либо напрямую через uvicorn:
# uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
После запуска приложение доступно в браузере:
- Главная страница: `http://127.0.0.1:8000/`
- Форма приветствия: `http://127.0.0.1:8000/greet`
- Таблица данных: `http://127.0.0.1:8000/table`
- Чат реального времени: `http://127.0.0.1:8000/chat`
- Интерактивная документация Swagger: `http://127.0.0.1:8000/docs`

## Непрерывная интеграция (CI)

В репозитории настроен пайплайн GitHub Actions ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)), запускающийся при каждом push и pull request. Пайплайн автоматически проверяет соблюдение стандартов PEP 8 с помощью `flake8` и прогоняет весь набор тестов `unittest`.
